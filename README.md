# OIMO · Продажи и команда

Внутреннее веб-приложение OIMO Technology (Бишкек): продавцы регистрируют продажи ноутбуков, владелец их проверяет, приложение считает план, рейтинг и KPI-начисления. Интерфейс на русском, валюта — сом (KGS), расчётные недели — понедельник–воскресенье по времени Бишкека.

Владельцу магазина: [пошаговое руководство](docs/OWNER_GUIDE_RU.md). Разработчику: [руководство разработчика](docs/DEVELOPER_GUIDE_RU.md).

Стек: Next.js 16 (standalone-сервер), Better Auth (email + пароль), SQLite (`better-sqlite3`), приватные фото на диске. Один процесс, одна папка данных, внешних сервисов не нужно.

## Что умеет

- Вход по **email и паролю** (пароль от 12 символов). Аккаунт ChatGPT или другой внешний вход не нужен.
- Роли «владелец» и «продавец». Все проверки прав выполняет сервер.
- После входа без магазина — два понятных пути: «Создать магазин OIMO» (вы становитесь владельцем) или «Открыть приглашение». Магазин создаётся только по нажатию; повторное нажатие не создаёт второй. `OIMO_SINGLE_STORE=true` оставляет на сервере только первый магазин.
- Владелец создаёт магазин и приглашает продавцов **персональной ссылкой** (действует 7 дней, принимается один раз, только аккаунтом с тем email, который указал владелец).
- Каталог с конфигурациями и ценами; в продаже сохраняется снимок модели и цены на момент продажи.
- Продажа: товар, фото, серийный номер, фактическая цена, способ оплаты (наличные, перевод, банковская рассрочка, мурабаха, онлайн-рассрочка) и получены ли деньги.
- Один серийный номер не может быть одновременно в двух активных продажах (проверяет база данных). Повторная отправка формы не создаёт дубль. Одно фото нельзя прикрепить к двум активным продажам.
- Владелец подтверждает, отклоняет (с причиной) или оформляет возврат. В KPI идут только подтверждённые ноутбуки.
- Отдельные планы на неделю, месяц и год (в штуках и/или в сомах) с нужным темпом в день; рейтинг за день, неделю, месяц и год; график.
- Показатели «сегодня / месяц / год», место в рейтинге и «сколько осталось до следующего уровня KPI».
- На компьютере — боковое меню; на телефоне — нижняя панель (Обзор · Продажи · «+ Продажа» · Начисления · Ещё) с учётом вырезов экрана, крупные зоны нажатия.
- Правила KPI с версиями: ступени, ставки, бонусы, два режима расчёта (см. ниже). Владелец утверждает формулу до закрытия первой недели.
- Ручные корректировки с причиной, закрытие завершённой недели (снимок не меняется), отметка уже сделанной выплаты.
- Выгрузка в Excel (настоящий XLSX): продажи недели и ведомость начислений. Текст в ячейках не может стать формулой.
- Журнал действий владельца. Смена пароля с завершением других сеансов.
- Демо-данные по желанию (вымышленные люди и продажи, цены только для примера). Рабочий магазин начинается пустым.
- Логотип OIMO (`public/oimo-logo.jpg`, присланный файл без изменений) на экране входа, в меню, на страницах приглашения и сброса пароля, как иконка вкладки.

### Формула KPI

Ступени по умолчанию (из ТЗ): 1–5 → 500 сом/шт.; 6–10 → 700 + бонус 2 000; 11–15 → 900 + 3 000; 16–20 → 1 100 + 4 000; 21–25 → 1 300 + 5 000; 26–30 → 1 500 + 6 000; 31–35 → 1 700 + 10 000.

В ТЗ пример противоречит формуле, поэтому есть два режима, и владелец выбирает сам:

- **«За каждую продажу»** (по умолчанию): число подтверждённых ноутбуков × ставка достигнутой ступени + один бонус этой ступени. 18 продаж → 18 × 1 100 + 4 000 = **23 800 сом**.
- **«Фиксированная ступень»**: верхняя граница ступени × ставка + бонус. 18 продаж → 20 × 1 100 + 4 000 = **26 000 сом** (как в примере ТЗ).

Больше 35 продаж: продолжает действовать последняя ставка (в фиксированном режиме — последняя фиксированная сумма). Пока формула не утверждена владельцем, неделю закрыть нельзя.

## Запуск на своём компьютере

Нужен Node.js 22.13 или новее (для `npm test` — 22.18+, 24 или 25) и npm.

```sh
npm ci
npm run setup     # создаёт .env.local со случайным секретом и базу data/oimo.sqlite; паролей не создаёт
npm run build
npm start         # открыть http://localhost:5188
```

Открывайте приложение **ровно по адресу из `BETTER_AUTH_URL`** (по умолчанию `http://localhost:5188`, а не `127.0.0.1`): запросы с другого адреса сервер отклоняет как чужие.

Для разработки вместо `build` + `start`: `npm run dev` (тот же адрес).

### Демо-вход для показа

При запущенном приложении:

```sh
npm run demo:owner -- --with-demo
```

Команда создаёт владельца `owner@oimo.local` со **случайным временным паролем** и магазин с вымышленными сотрудниками и продажами, печатает данные и сохраняет их в `DEMO_CREDENTIALS.txt` (файл не попадает в git, Docker-образ и архив). Повторный запуск выдаёт новый пароль и завершает старые сеансы. После входа смените пароль: «Пароль и безопасность» (на телефоне — «Ещё»). Без `--with-demo` магазин создаётся пустым.

Перед реальной работой начните с чистой базы: остановите приложение, перенесите папку `data/` в архив и выполните `npm run setup`.

### Первые шаги

1. Нажмите «Создать аккаунт», укажите имя, email и пароль. Первый аккаунт ничем не отличается от остальных: владельцем становится тот, кто создаёт магазин.
2. Создайте магазин. Галочка «Добавить демо-команду» загружает вымышленные данные — только для показа; для работы оставьте её пустой.
3. «Начисления → Правила KPI»: проверьте режим и ступени, утвердите формулу.
4. «Каталог товаров»: добавьте модели и цены.
5. «Команда → Пригласить»: имя и email продавца. Приложение покажет персональную ссылку — скопируйте её и отправьте сотруднику сами (мессенджер, лично). Писем приложение не отправляет.
6. Сотрудник открывает ссылку, регистрируется **с тем же email** и своим паролем, нажимает «Принять приглашение». Если ссылка потерялась или истекла — «Новая ссылка» в списке команды; старая сразу перестаёт работать.
7. Продавец добавляет продажу с фото, владелец подтверждает её во вкладке «Продажи».

Один аккаунт = один магазин (владелец или продавец). Отключённый сотрудник теряет доступ к данным и фото на следующем же запросе.

### Забыли пароль

- **Без почты (по умолчанию).** Тот, у кого есть доступ к серверу, выполняет
  `npm run admin:reset-password -- user@example.com`
  Скрипт задаёт временный пароль, завершает все сеансы аккаунта и показывает пароль один раз в терминале. Передайте его человеку лично; после входа он меняет пароль через пункт «Пароль и безопасность» в боковом меню. Ссылка «Забыли пароль?» в этом режиме честно говорит, что почта не подключена.
- **С почтой.** Заполните `SMTP_*` в `.env.local` (или `.env.docker`) и перезапустите. Появится сброс пароля по письму и письмо подтверждения email при регистрации. В этом режиме принять приглашение можно только с подтверждённым email. Отправку писем с реальным SMTP-сервером мы не проверяли — проверьте на своём ящике.

## Запуск в Docker

```sh
node scripts/docker-env.mjs        # один раз: создаёт .env.docker со случайным секретом (в git и в образ не попадает)
docker compose up -d --build
# открыть http://localhost:5190
```

- Данные (база и фото) лежат в томе `oimo-data` (`/data` в контейнере) и переживают пересборку. `docker compose down -v` **удаляет** их.
- Миграции применяются при каждом старте автоматически. Процесс работает от непривилегированного пользователя `node`.
- По умолчанию порт открыт только для этого компьютера (`127.0.0.1:5190`). Другой порт: `OIMO_PORT=5300 node scripts/docker-env.mjs` и `OIMO_PORT=5300 docker compose up -d`.
- Сброс пароля: `docker compose exec oimo node scripts/admin-reset-password.mjs user@example.com`.
- Резервная копия: `docker compose exec oimo node scripts/backup.mjs /data/backups`, затем `docker compose cp oimo:/data/backups ./backups`.

> **Контейнер на этом Mac не собирался и не запускался**: Docker Desktop не стартует с ошибкой «no space left on device» внутри своей виртуальной машины (при этом на Mac около 31 ГБ свободно; данные Docker не удалялись). Проверено то, что возможно без Docker: файл compose валиден, а раскладка файлов образа (standalone-сервер + миграции + скрипты, без лишних зависимостей) запущена на macOS — миграции, вход, логотип и скрипт сброса пароля работают. Перед передачей другу один раз выполните `docker compose up -d --build` там, где Docker работает.

## Доступ с телефонов в магазине

По умолчанию приложение доступно только на том компьютере, где запущено.

### Быстрый вариант для теста (Wi-Fi, без HTTPS)

```sh
npm run lan                 # слушать все сетевые интерфейсы, доверять адресам этого Mac
launchctl kickstart -k gui/$(id -u)/com.oimo.sales   # если приложение запущено службой launchd; иначе перезапустите npm start
```

Команда печатает адреса для телефона, например `http://192.168.1.100:5188` и `http://MacBook-Air.local:5188`. Адрес по IP открывается на любом телефоне; имя `.local` — на iPhone и большинстве Android 12+. Если роутер выдал Mac другой IP, ничего менять не нужно: сервер сам перечитывает свои адреса раз в 30 секунд. Ссылки-приглашения, созданные на самом Mac (`localhost`), автоматически получают адрес для телефона.

Разрешённые адреса: `BETTER_AUTH_URL`, `localhost`/`127.0.0.1` на том же порту, `OIMO_TRUSTED_ORIGINS` и собственные LAN-адреса Mac. Запросы с любых других адресов и сайтов отклоняются (защита от CSRF).

> ⚠️ **`OIMO_OPEN_TEST_ACCESS=true` (`npm run lan -- --test`) — только для теста без реальных данных.** В этом режиме принимается любой адрес локальной сети, если запрос пришёл с той же страницы (Origin совпадает с Host). Вход, сеансы и права ролей продолжают проверяться, но сетевой доступ шире. Сайты из интернета по-прежнему отклоняются. По умолчанию режим выключен; при запуске сервер пишет предупреждение. Выключить: удалите строку `OIMO_OPEN_TEST_ACCESS=true` из `.env.local` и перезапустите.

Ограничение: по обычному `http://` пароли и сеансы идут по Wi-Fi открытым текстом. Для реальной работы нужен HTTPS.

### Для реальной работы (HTTPS)

Рекомендуемый вариант — поставить перед приложением обратный прокси с HTTPS (например, Caddy или nginx), затем:

1. `BETTER_AUTH_URL=https://адрес-который-вводят-в-браузере` (тогда cookie автоматически становятся `Secure`).
2. `TRUSTED_PROXIES=` IP или подсеть прокси (например, `172.16.0.0/12` для Docker-сети), чтобы сервер видел настоящие IP клиентов. Прокси должен перезаписывать или дописывать `X-Forwarded-For`.
3. Открыть порт приложения только для прокси, а не для всей сети.

В Docker адреса Mac изнутри контейнера не видны: для временного показа опубликуйте порт как `"0.0.0.0:5190:5188"` и перечислите адреса в `OIMO_TRUSTED_ORIGINS` (например, `http://192.168.1.100:5190`).

## Резервные копии и восстановление

- `npm run backup` (локально) делает согласованную копию базы (безопасно при работающем приложении) и папки фото в `backups/oimo-<дата>/`.
- Делайте копию ежедневно и храните её **вне этого компьютера** (внешний диск, облако владельца). Раз в месяц проверяйте восстановление на другой машине.
- Вместе с копией храните `BETTER_AUTH_SECRET` из `.env.local` / `.env.docker`. Без него все сеансы сбросятся (пароли останутся рабочими), но приложение запустится.
- Восстановление: остановить приложение → положить `oimo.sqlite` и `photos/` из копии в папку данных (`data/` или том `/data`), удалить старые `oimo.sqlite-wal` и `oimo.sqlite-shm` → запустить.

## Проверки

```sh
npm run typecheck          # TypeScript strict
npm run lint               # ESLint (0 ошибок; предупреждения о <img> и неиспользуемых иконках допустимы)
npm test                   # 7 групп доменных тестов: KPI, деньги, недели, серийники, XLSX
npm run build
npm run test:isolated      # собранный сервер на :5199 с временной базой: 21 сквозной сценарий + 9 проверок (в т.ч. LAN-адреса)
npm run test:e2e -- http://192.168.1.100:5188   # необязательно: весь сценарий через настоящий интерфейс в Chrome (нужен `npm i --no-save puppeteer-core`; создаёт тестовые аккаунты на этом сервере)
```

Визуальная проверка (скриншоты iPhone SE, Android, компьютер; владелец и продавец; загрузка, ошибка, пустой магазин, длинные названия, фокус клавиатуры) лежит в `outputs/visual-qa/` рабочей папки; в архив исходников не входит.

`test:isolated` никогда не трогает `data/`: он создаёт временную базу, поднимает production-сервер, прогоняет `tests/integration.mjs` (регистрация и вход по паролю, роли, приглашения, продажи, гонки, закрытие недели, лимиты входа, смена пароля) и удаляет всё за собой. `npm run test:integration` запускает те же сценарии против уже работающего сервера (`OIMO_TEST_ORIGIN`, только localhost) и создаёт в его базе тестовые магазины — не запускайте его против рабочих данных.

## Ограничения пилота

Это рабочий пилот для небольшой команды, а не ERP и не бухгалтерская программа.

- Возврат в **открытой** неделе освобождает серийный номер и пересчитывает начисления. Возврат после **закрытия** недели заблокирован: оформите финансовую корректировку в текущей неделе вручную. Серийный номер такой продажи остаётся занят, поэтому повторно продать этот экземпляр в приложении нельзя, пока не появится модуль возвратов.
- «Отметить выплату» только фиксирует уже сделанный платёж; деньги приложение не переводит. Это не налоговая и не трудовая ведомость.
- Статус оплаты фиксируется при создании продажи. Графиков рассрочки и сверки поступлений нет.
- Нет складских остатков, закупок, себестоимости, маржи, налогов, интеграций с кассой, банками или Telegram.
- Аксессуары входят в выручку, но не в количество ноутбуков для KPI.
- Проверка фото — это проверка формата (JPG/PNG/WebP до 6 МБ), а не антивирус и не доказательство продажи.
- Данные загружаются целиком, без серверной постраничной выдачи — рассчитано на небольшую команду. Перед импортом большого архива нужна пагинация.
- Без SMTP email не подтверждается: защита приглашения держится на секретной ссылке. Не пересылайте ссылки в общие чаты.
- Лимиты входа: 10 неудачных попыток на email за 15 минут (затем пауза), плюс общие лимиты на регистрацию и сброс. Злоумышленник, знающий email, может временно (до 15 минут) заблокировать вход этому аккаунту — это осознанный компромисс против подбора пароля.
- Демо-данные вымышлены; цены в них — для примера, а не текущий прайс.
