# Приёмка пилота OIMO

Проверено 24 октября 2026 на macOS (Node.js 25.8.2), Next.js 16.4.3, Better Auth 1.7.12, SQLite. `npm audit --omit=dev`: 0 уязвимостей (Next.js обновлён с 16.3.4 из-за опубликованных уязвимостей).

## Автоматические проверки (выполнены, все прошли)

- `npm run typecheck` — TypeScript strict, без ошибок.
- `npm run lint` — 0 ошибок (остались предупреждения: `<img>` для логотипа и фото, неиспользуемые иконки).
- `npm test` — 7 групп доменных тестов: границы ступеней (0, 1, 5, 6, …, 35, 36 продаж), 23 800 / 26 000 сом при 18 продажах в двух режимах, следующий бонус, граница недели и года по Бишкеку, точные суммы в тыйынах, нормализация серийного номера, права на объект, неверные ступени, XLSX без формул.
- `npm run build` — production-сборка standalone.
- `npm run test:isolated` — собранный сервер с временной базой, реальная регистрация и вход по паролю, cookie-сеансы (21 сценарий + 9 проверок):
  1. Без входа → 401; запись с чужого Origin → 403.
  2. Регистрация с email из приглашения не даёт доступа; токен привязан к email и погашается один раз; чужое и поддельное приглашение отклоняются.
  3. Одновременные «принять приглашение» и «создать магазин» оставляют аккаунт ровно в одном магазине.
  4. Новая ссылка аннулирует старую; привязанному сотруднику ссылку создать нельзя.
  5. Продавец не управляет каталогом, командой, ссылками, правилами, планами, закрытием, корректировками, выплатами и не выгружает ведомость (403).
  6. Повтор отправки не дублирует продажу; одно фото нельзя прикрепить к второй активной продаже; продавец назначается сервером; цена хранится точно; серийный номер нормализуется.
  7. Изменение каталога не меняет исторические продажи.
  8. Нет доступа к чужому магазину и его фото; продавец не может использовать фото другого сотрудника.
  9. Два одновременных подтверждения → одно успешное, одна запись аудита.
  10. Возврат пересчитывает открытую неделю и позволяет снова продать этот серийный номер.
  11. Без утверждённой формулы неделю закрыть нельзя; закрытая неделя отвергает поздние продажи, возвраты и корректировки.
  12. Выплату нельзя отметить дважды; корректировка сохраняется точно.
  13. Владелец получает настоящий XLSX ведомости.
  14. Одновременное сохранение правил и подтверждение продажи сообщают фактический результат, аудит совпадает.
  15. Слишком большое тело запроса → 413 до изменения данных.
  16. SVG под видом PNG отклоняется; отключённый сотрудник сразу теряет доступ к API и фото.
  17. 10 неудачных входов на один email (с подменой `X-Forwarded-For` на каждом запросе) → дальше 429 даже с верным паролем; вход других аккаунтов работает.
  18. Смена пароля завершает другой сеанс, старый пароль перестаёт работать, новый работает.
  19. Поддельные заголовки старой платформы → 401; неверный пароль → 401; выход отзывает сеанс.
  20. Рейтинги за день/неделю/месяц/год учитывают подтверждение и отдают продавцу только имена и количество.
  - Режим одного магазина: из двух одновременных первых регистраций магазин создаёт ровно одна; дальше — только по приглашению.
  - `demo:owner`: случайный пароль входит как владелец с демо-данными; повторный запуск выдаёт новый и отзывает старый.
  - Страницы отдают CSP и не содержат упоминаний ChatGPT/Claude/Codex/OpenAI.
  - Онбординг: пользователь без магазина создаёт его явным действием; двойное нажатие — один магазин, сразу панель владельца; сотрудник другого магазина получает 409.
  - LAN-адреса: указанный IP, `127.0.0.1` и собственный IP Mac принимаются для регистрации и действий; чужой IP и сторонние сайты — 403.
  - `OIMO_OPEN_TEST_ACCESS`: любой локальный Host/IP при совпадении Origin; чужой или несовпадающий Origin — 403; без входа — 401; по умолчанию выключен.
  - Истёкшее приглашение отклоняется.
  - Скрипт `admin-reset-password`: временный пароль работает, старый пароль и сеансы отозваны.
  - Демо загружается только в пустой магазин (34 продажи, 3 вымышленных сотрудника); XLSX продаж выгружается.
  - Главная, `/join`, `/reset-password` отвечают 200; страница и иконка используют присланный логотип.
- Схема: миграции на пустой базе создают все таблицы; программная проверка Better Auth не находит недостающих таблиц, колонок и индексов.
- Раскладка Docker-образа (standalone + `migrations/` + скрипты, без `node_modules` проекта) запущена на macOS: миграции при старте, регистрация, логотип, скрипт сброса пароля работают. `docker compose config` валиден.
- `npm run backup` на работающем приложении: копия проходит `PRAGMA integrity_check`.
- Сборка не содержит локального секрета (проверено поиском значения в `.next`).
- **Сценарий через настоящий интерфейс по Wi-Fi-адресам** (Chrome, чистые контексты, размер телефона): регистрация владельца → создание магазина → товар → фото и продажа → подтверждение → приглашение → продавец открывает ссылку в чистом браузере, регистрируется, принимает приглашение → продажа продавца с фото → отклонение с причиной → продавец видит отклонение. 13 из 13 шагов, ошибок HTTP и консоли нет — на рабочей службе launchd по `http://192.168.1.100:5188`, `http://MacBook-Air.local:5188`, `http://localhost:5188`, `http://127.0.0.1:5188`, а также на отдельном экземпляре без тестового режима (только `OIMO_TRUST_LAN`). Скриншоты: `outputs/visual-qa/lan-e2e/`.
- Визуальная проверка в headless Chrome: 37 скриншотов в `outputs/visual-qa/` (владелец и продавец; вход, ошибка входа, регистрация, загрузка, ошибка сервера, пустой магазин, длинные русские названия, детали продажи, лист «Ещё», рейтинг за месяц, планы, начисления, команда, фокус клавиатуры, ссылка «Перейти к содержимому», живой демо-вход и смена пароля). Горизонтальной прокрутки и ошибок консоли/CSP нет.
- axe-core (WCAG 2 A/AA) на 7 ключевых экранах: 0 нарушений. Зоны нажатия на телефоне не меньше 44 px (карточка продажи нажимается целиком — проверено hit-test).
- Демо-вход на рабочем сервере: вход через форму под `owner@oimo.local` открывает панель владельца, форма смены пароля доступна.

## Что не проверено

- **Docker-контейнер не собирался и не запускался**: Docker Desktop на этом Mac не стартует — «no space left on device» внутри его виртуальной машины (повторная попытка 24.10 при 31 ГБ свободного места на Mac; данные Docker не удалялись). Перед передачей выполните `docker compose up -d --build` на машине с рабочим Docker.
- Реальные телефоны: проверка шла в headless Chrome с размерами iPhone SE (375×667), Android (412×915) и компьютера (1440×900). На живом iPhone/Android (вырезы экрана, съёмка фото камерой) нужно один раз пройти вручную.
- Отправка писем через реальный SMTP-сервер (сброс пароля, подтверждение email).
- Работа за HTTPS-прокси и с `TRUSTED_PROXIES`.

## Перед реальными начислениями

Владелец утверждает категории KPI, формулу на нескольких примерах, правила возвратов и порядок выплаты. Команда проходит одну неделю параллельно с контрольной ведомостью. Нужно назначить ответственного за сервер, настроить ежедневную копию вне компьютера и проверить восстановление, включить HTTPS для доступа с телефонов. Это пользовательская приёмка, её не заменяет успешная сборка.
